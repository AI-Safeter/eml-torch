# Evaluation details frozen before opening the gate

Training remains governed by the original protocol and immutable training-source hashes. These details were fixed using engineering checks and selection data, before gate or final model-quality evaluation.

* Deploy every nonlinear student with its affine input/output statistics folded into the encoder/decoder. Deploy each factorized linear student as one dense affine map when that uses fewer coefficients. Count the resulting parameters and buffers. CUDA validation must show FP32 folding NRMSE below 1e-4 on both selection domains; separately report BF16 conversion error. This gives the linear control the cheaper equivalent inference path.
* ARC continuation scores use one unpadded candidate at a time with native full logits. A batched, truncated-logit implementation differed from independent native scoring by as much as .125 nats/token in a selection check. It was rejected before gate evaluation. The final scorer agrees with independent log-softmax scoring to below 1e-5 nats/token. This is a numerical execution choice, not a change of task labels or scoring objective.
* Use alpha .05/(5 endpoints × 3 seeds) within each model family for the expansion decision. This tightens the earlier accuracy-only adjustment. Report net paired accuracy change and its 95% interval, alongside the conservative regression upper bound used for acceptance.
* For arithmetic, treat both formats of one operand pair as one group. The acceptance bound covers the event that either format regresses. For language, keep the preregistered document bootstrap and also require a hostname-clustered sensitivity bound to pass before expansion. This extra conservative condition was fixed before the gate.
* Evaluate all three seeds of the validation-selected configuration in each family. Also evaluate SiLU at the selected EML depth/budget and the corresponding linear budget, when these differ from their independently selected configurations. No seed is discarded because of test performance.
* Retain the 24-token, integer-only arithmetic task unchanged. On the small selection pilot, the original model answered division prompts with prose and failed this output contract. A zero original score cannot demonstrate preservation of division competence. Report the zero score unconditionally and label that task uninformative for arithmetic retention; do not silently substitute a different parser or token budget.
* Benchmark the fully GPU-resident native BF16 model and deployed students with identical eager SDPA execution. No compiled inference claim is made. The original MLP is absent in measured replacement paths. The primary workload and 10 warm-ups/50 paired repetitions remain unchanged. Other processes share the H100; report that limitation and distinguish allocated/reserved PyTorch memory from total-device telemetry.

The small first-seed selection pilot is a diagnostic only. It cannot certify a utility target. A failed one-block gate prevents multi-block expansion. The final holdout evaluates the frozen candidate without subsequent tuning.
