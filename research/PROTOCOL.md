# Scalar arithmetic-component replacement

This study asks whether a small function of upstream activations can reproduce one causally relevant scalar contribution inside a language model. It does not replace a whole MLP, identify a human arithmetic concept, or accelerate the complete language model.

Qwen3-1.7B is pinned to revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`. The Qwen3-0.6B replication uses revision `c1899de289a04d12100db370d81485cdf75e47ca`. Models run in float32 on H100 GPUs, with TF32 disabled and model weights frozen. Each operation is localized and fitted separately.

Prompts use the model's chat template with thinking disabled and the assistant prefill `The answer is `. Greedy generation allows eight new tokens. Complete-answer scoring requires the entire generated continuation to be numeric, apart from whitespace and an optional final period or exclamation mark. These are accuracy measurements under this specific prompting and parsing protocol, not general model benchmark scores.

The frozen data contain addition, multiplication, and exact integer division. A problem pairs clean operands `(a, b)` with corrupted operands `(c, b)`. Answers have equal digit lengths and different first digits. This contrast condition makes the causal margin measurable; the sample is not an unrestricted arithmetic benchmark. Clean and corrupted operand problems are disjoint between training, validation, and test sets, including commutative duplicates. Previously evaluated addition pairs are excluded. The smaller model uses the same frozen operands, so it supplies a model replication rather than an independent data replication.

Addition and multiplication use 1,024 training and 256 validation pairs each; division uses 768 and 192. Each pair appears in prose, symbolic, and Python-expression formats. Tests hold out 256 pairs for addition/multiplication and 192 for division, introduce a fourth instruction format, and shift the operand ranges. Addition also reserves a difficult units-carry pattern. Counts, precise sampling rules, dataset hashes, and model revisions are saved in each operation's protocol.

Training activation patching selects three candidate MLP layers. Validation then selects one direction from four principal directions of training clean–corrupt output differences and their mean direction. This validation step is part of model selection and is disclosed in `localization.json`.

For a selected unit direction `d`, the target is the scalar `c(h) = dᵀ MLP(h)`. Training inputs interpolate between corrupted and clean upstream activations at strengths 0, 0.25, 0.5, 0.75, and 1. A replacement predicts this scalar from upstream inputs and changes only the output contribution along `d`. The patch divides by the actual `dᵀd`, preserving the orthogonal output. During ordinary generation it applies only at the last prompt position on the initial prefill.

Two feature encoders are compared: 32-dimensional PLS fitted to training coefficients, and 32-dimensional active subspaces fitted to training input-gradient outer products. The latter uses the uncentered covariance, retaining the mean gradient. Validation gradients audit the fitted basis but do not fit it. The method follows [gradient-based active subspaces](https://arxiv.org/abs/1408.0545); active subspaces are established prior work.

The EML heads have learned affine arguments, a linear skip, and a scalar readout. The main positive-log form uses `exp(aᵀz + b) - log(1 + (uᵀz + v)²)`, with the core operator's numerical guards. A log-only subfamily and ordinary SiLU heads are controls. These are trained equation-shaped networks, not expressions discovered by the repository's discrete tree search. Learned symbolic neural networks have substantial prior work, including [equation learning](https://arxiv.org/abs/1912.04825) and [learned EML heads](https://arxiv.org/abs/2604.13871).

All heads fit normalized scalar values and coefficient responses. The primary objective is absolute MSE plus four times response MSE; a zero-response-weight search is an ablation. A separate active-feature search also fits input derivatives, weighted by 0.1 after normalizing gradient MSE by training gradient energy. Checkpoint selection still uses the value-and-response validation objective. Widths, seeds, stopping rules, completed candidate counts, and timing limits are recorded. The smaller-model replication fixes width 32 and 12,000 maximum optimization steps before its tests.

A sparse original-neuron control selects SwiGLU units by training orthogonal matching pursuit and refits their scalar readout on the same value-and-response objective. Sixteen units have approximately the same input-weight storage as a rank-32 encoder. A second control selects among 4, 8, 16, 32, and 64 units using validation. This control retains the original activation primitive and input weights; it does not use an EML head.

Selection files freeze checkpoint and component hashes before test evaluation. The primary test reports complete-answer accuracy and model-margin responses at interpolation strengths 0.125, 0.375, 0.625, and 0.875, which were absent from fitting. Responses are measured relative to strength zero separately for each replacement. Response NRMSE divides error RMS by the original model's response RMS. The declared point criteria are an accuracy loss no larger than one percentage point, response correlation at least 0.9, and response NRMSE no larger than 0.2. More conservative checks use the corresponding confidence-interval limits.

A secondary diagnostic independently changes active input coordinates 0, 1, 7, and 31 by ±0.25 training standard deviations, using the first 32 frozen test pairs in the three known formats. These are local, potentially off-manifold interventions. They are not used to select heads. The implementation checks that the intended coordinate changes while the other coordinates remain fixed within floating-point tolerance.

Uncertainty uses 5,000 paired bootstrap resamples of operand groups. Prompt formats, intervention strengths, and coordinate edits remain together within each resampled group. EML–neural differences use paired errors. Broad validation tuning and multiple exploratory comparisons are disclosed; a threshold pass is not a claim of unique EML superiority.

The accuracy-change bootstrap can collapse to [0, 0] when all observed group differences are zero. Such an empirical interval does not certify the absence of rare unseen regressions or establish a distribution-free one-percentage-point noninferiority guarantee. The declared interval checks are descriptive bootstrap checks, with this finite-sample limitation. Continuous response-error intervals are reported separately.

Native CUDA timing concerns the standalone scalar predictor. Its teacher baseline folds the final output projection into a scalar readout, avoiding an unfair comparison against a full MLP output. Both EML and SiLU heads have native implementations. CUDA graphs contain repeated calls to avoid Python replay gaps. The machines are shared, so timing variability and execution conditions accompany every measurement.

Exact-restoration logits and complete generation, zero-strength references, coefficient exports, coordinate edits, and analytic metric controls are validated on CUDA before testing. Raw results preserve failed and successful variants. The core repository remains separate from these application and research artifacts.

Follow-ups are explicitly exploratory. A linear least-squares control uses the same training value/response objective and validation selection, then folds its feature projection into one input vector. The smaller-model linear control was added after its first test results; its fit still uses no test values. Original selections are preserved alongside supplementary files.

The compact-head follow-up freezes 96 additional operand pairs per operation, disjoint from every original split. Its grid uses ranks 2/4/8/16, widths 1/2/4/8, seeds 17/29, and EML-square/log/SiLU heads, with 8,000 maximum steps. Validation selects the smallest encoder-plus-head with both value and response MSE at most 0.005; otherwise it reports the best validation candidate and a threshold failure. The 1.7B follow-up is addition only and shares its extra operand cohort with the smaller-model follow-up. Storage fields exclude normalization and the intervention direction; they are not complete model sizes.

Four further 1.7B addition seeds (59/71/83/97) use fixed active-32 features, width 32, gradient weight 0.1, and EML-square/SiLU-two heads. Every seed is evaluated on the same additional 96-pair cohort. This checks initialization dependence conditional on the fixed encoder, not the entire pipeline. The seed protocol precedes the new fits, and no winner is selected across their evaluation results.

The airfoil application is a replay of an earlier evaluated split. It distills a frozen five-input neural teacher using training points, synthetic mixtures within training bounds, and teacher gradients. Validation selects among 48 EML/SiLU candidates. Ground-truth test and range-shift results are disclosed with grouped uncertainty, but they are not a fresh confirmation. Standalone Python and C exports are compared with saved CUDA predictions. Both teacher and EML scalar CPU timings use the same C compiler flags.

Reproduction changes make timing limits explicit CLI options instead of reading the original session deadline. Frozen evidence and selection files are preserved. Published source adds portability checks and report generation after the experiments; source packaging time must not be mistaken for the time a protocol or checkpoint was originally frozen.
