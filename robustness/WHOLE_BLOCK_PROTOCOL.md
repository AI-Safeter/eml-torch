# Prospective whole-block experiment

This is a separate utility experiment, frozen before student fitting. It tests Qwen3-1.7B at the layer selected by Stage A addition localization using training and validation only. Replace that entire MLP module at every prompt and generated position. The original MLP must never execute in the replacement path. All model weights outside the replacement remain frozen.

## Data

Use the pinned Qwen model in `models.json` and Salesforce/wikitext, subset `wikitext-2-raw-v1`, revision `b08601e04326c79dfdd32d625aee71d232d685c3`. Preserve its official train, validation, and test splits. Concatenate nonempty text with two newlines, encode without added special tokens, and partition into nonoverlapping 256-token blocks. Training uses the first 2,048 blocks after a seeded shuffle (20260924), validation 128, and test 256; use all blocks when a split is smaller. Record exact token/block hashes. The test split is never used to fit, choose a checkpoint, or choose width. This familiar public corpus is a language retention check, not evidence of absence of pretraining contamination.

Collect original MLP inputs and outputs at every real token in the first 512 Stage A training pairs per operation across all three training formats, and the first 128 validation pairs likewise. Include clean prompts and their numeric answer continuations. Padding tokens are excluded. Separately collect the language blocks. Uniformly sample at most 131,072 training and 16,384 validation token activations from each domain. Save indices. Both domains contribute equally to the fitting and validation loss regardless of token counts. Arithmetic tests use all Stage A primary and unconditioned test cases and all three formats, with 16-token greedy generation. No test activation is used for fitting.

## Fixed students and fitting

The primary EML vector student has two learned input affine maps, elementwise `safe_eml(left(x), 1 + right(x)**2)`, and an output affine map. There is no full-width linear skip and no original-MLP residual. Widths are 128, 256, and 512. The parameter-matched nonlinear control uses the identical affine maps and widths with `silu(left(x)) * right(x)`. A factorized linear control has ranks 192, 384, and 768, giving approximately the same coefficient budget as each nonlinear width; report exact counts including biases and normalization. Neither family gets an extra hyperparameter search.

Normalize inputs by training per-coordinate mean and standard deviation, outputs by training mean and one global RMS scale. Compute those statistics from an equally weighted arithmetic/language mixture. Store and count these constants; fold affine normalization at deployment where possible. All models learn both the constant and varying output. Use seeds 101, 211, and 307 for all families and widths. AdamW learning rate .001, weight decay .0001, batches of 1,024 token activations (512 per domain), gradient norm clip 1, up to 20,000 updates. Validate every 100 steps. Stop after 2,500 nonimproving steps once at least 3,000 steps have run. Minimize equally weighted domain normalized output MSE. Select one seed and width per family by this validation objective. Report all fits, failed fits, and coefficient counts. Freeze selected checkpoint hashes before any test evaluation.

## Evaluation and criteria

Report held-out per-domain output NRMSE; per-block language cross-entropy in nats/token; arithmetic complete-answer accuracy and paired losses; and numerical stability. Primary utility criteria are (1) at least 4x reduction in this block's stored float32 coefficients, including constants; (2) a one-sided 95% paired block-bootstrap upper bound on mean language cross-entropy increase <= .02 nats/token; (3) a conservative 95% accuracy-loss upper bound <= 1 percentage point for each operation on the unconditioned cohort, using the same three-threshold construction with Bonferroni correction across three operations; and (4) no nonfinite outputs. Report failure of any criterion. These criteria apply to the validation-selected EML student, with equally budgeted controls reported alongside it. An EML-specific advantage requires paired evidence over the control, not just passing a teacher-retention threshold.

Measure actual whole-model prefill and decode latency in float32 with batch sizes 1 and 8, 128-token inputs, and 32 fixed decode steps. Use identical pretokenized inputs and token budgets; synchronize CUDA, warm up 10 times, collect 50 paired measurements alternating baseline/replacement order. Decode timing excludes prefill, uses cached keys/values, and forces the same predetermined token sequence to avoid content-length confounds. Report both phases, distributions, GPU sharing, and standalone block timing. Eager and compiled results must be labeled separately. No speedup claim unless the observed end-to-end improvement exceeds measurement uncertainty. A single replaced block may have negligible whole-model impact even when block compression succeeds.
